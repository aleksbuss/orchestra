## 🧠 Core Agentic Subsystems (New Architecture)

### 1. Mixture-of-Agents (MoA) Ensemble (`src/lib/agent/moa.ts`)
- **Dynamic Persona Generation (DPG):** Instead of static roles, the Router dynamically spawns 3-5 hyper-specialized experts based on the exact user prompt.
- **Single source of truth for activation: the UI toggle `swarmEnabled`.** When the user enables Swarm, MoA always runs — `agent.ts:runAgent` does NOT regex-filter the message. (See PM #9 — an earlier `queryNeedsMoA` regex on the entry path silently overrode the UI for non-whitelisted verbs and was removed.)
- **Internal Bypass (Router decision, NOT a UI override):** the Router inside MoA may set `requiresSwarm: false` for trivial prompts and answer directly from a single model — saves tokens on "thanks" / "hi" without spinning up 3–5 proposers. This is an *internal* MoA optimization; it never bypasses the user's intent to use Swarm. Note: a weak `utilityModel` (the Router runs on `settings.utilityModel`) can mis-classify substantive prompts as trivial — if you see surprising direct answers under Swarm-ON, upgrade `utilityModel` from a free/low-quality model to something stronger.
- **Force Swarm escape hatch (user override of the Router — PM #22):** the UI exposes a `forceSwarm` toggle (amber "Force" pill in [`src/components/chat/swarm-config.tsx`](src/components/chat/swarm-config.tsx), only visible when Swarm is ON). When set, `runMoAEnsemble` ignores `dpgResult.requiresSwarm` and always fans out the proposers. Wired end-to-end through Zustand → `chat-panel` body → `/api/chat` → `runAgent` → `runMoAEnsemble` for the **interactive** transport AND through `dispatchAgentJob` → `runBackgroundJob` → `runAgent` for the **background / Auto-Pilot** transport (the second path was added in the 2026-05 audit follow-up after it was discovered to silently drop the override — see PM #22 closing notes). The persisted `data/queue/<chatId>.json` entry written by `enqueueJob` carries `forceSwarm` too, so a server restart mid-Auto-Pilot resumes with the override intact. **Rule:** any *user-facing* feature toggle that can be short-circuited by an *internal* optimisation must ship with a `force<Feature>` escape hatch in the same PR — and that escape hatch must be threaded through EVERY dispatch path (interactive stream, background dispatch, queue persistence, daemon recovery), not just the one the original PR exercised. If a future PR adds another inner gate that can countermand user intent, add the matching override alongside it and audit every dispatch entry-point — do not wait for a user to report the silent override.
- **Zero-Latency Fact-Checking:** One of the DPG roles is *always* forced to be a "QA Auditor / Skeptic" who fact-checks claims in parallel with the other proposers. **The injection is UNCONDITIONAL (PM #91)** — `generateDynamicSwarm` ([`moa-router.ts`](src/lib/agent/moa-router.ts)) injects the canonical critic on `if (!hasSkeptic)`, NOT `if (object.requiresSwarm && !hasSkeptic)`. The old `requiresSwarm` gate left the `forceSwarm`-over-bypass corner (user Forces the swarm + Router judged the prompt trivial) fanning out with no guaranteed Skeptic — the Router can't see `forceSwarm`, so it must guarantee the skeptic regardless of its own bypass verdict; on a genuine bypass the injected critic is discarded for free before any proposer runs. **Rule:** enforce a guaranteed-persona invariant wherever the swarm can FAN OUT, never gated on the Router's own "will it run?" decision. **Eval-only control arm (Skeptic-eval Step 2):** `ORCHESTRA_EVAL_SKEPTIC_CONTROL=true` — honored ONLY when `NODE_ENV !== "production"` — makes `applySkepticControlArm` ([`moa-router.ts`](src/lib/agent/moa-router.ts)) swap every reviewer persona for a neutral analyst of the SAME slot, yielding a same-headcount swarm with NO Skeptic so an A/B ([`docs/moa-skeptic-control-ab.md`](docs/moa-skeptic-control-ab.md), over PR #51's `fact-trap` cases) can isolate the Skeptic's causal value. Strict no-op with the flag unset (the default) or in a production build — the invariant above holds on every real run. NEVER set in production.
- **Tool-less proposers must be TOLD they're tool-less (PM #77).** Proposers run without tools by default (search_web only with a key — PM #68; code_execution only on opt-in — PM #50). `augmentProposerPromptForTools` ([`moa-proposer-tools.ts`](src/lib/agent/moa-proposer-tools.ts)) appends `PROPOSER_NO_TOOLS_DIRECTIVE` for an empty/undefined toolset — the proposer-side mirror of PM #61's `PLAIN_CHAT_TOOL_OVERRIDE`. Without it, a tool-demanding user prompt ("run the code", "use the code_execution tool", "search…") makes non-code personas return `(empty draft)` instead of reasoning in prose; empties are dropped by `isSuccessfulDraft`, shrinking the ensemble below the ≥2 the inline-synthesis collapse needs. NB: this is NOT a reasoning-channel/`.text`-extraction bug — gemini-2.5-flash and deepseek-r1 both populate `.text` fine; the trigger is the tool demand, confirmed by isolation repro.
- **Proposers must be GROUNDED in the active task (PM #94).** Proposers do NOT inherit the agent's system prompt (active goal + deep-memory recall), and their history comes from `safeHistory` ([`moa-setup.ts`](src/lib/agent/moa-setup.ts)), which STRIPS every tool result + tool-call assistant message for pairing-safety (a strict-provider 400 hazard). That strip also removes the task context those messages carry (goal-tracker `update_task_status`, file edits, command output) — so a bare continuation prompt ("Продолжай" / "continue") left proposers with nothing to continue: each refused ("уточните, что продолжить"), the identical refusals read as `consensus` by the divergence-only disagreement detector ([`disagreement.ts`](src/lib/agent/disagreement.ts)), and `buildInlineSynthesisInjection`'s "MUST synthesize these drafts" directive steered the brain into echoing the refusal → a one-line, ZERO-tool-call, `200` no-op turn. Fix: `buildProposerContextBlock(history)` ([`moa-prompts.ts`](src/lib/agent/moa-prompts.ts)) re-supplies the stripped context as a plain-text block appended to the proposer SYSTEM prompt (NOT a re-inserted message — that would reintroduce the orphaned-pair 400 the strip avoids), flattening the last N history messages INCLUDING tool-call/tool-result parts (strictly richer than the Router's text-only flatten in [`moa-router.ts`](src/lib/agent/moa-router.ts), which drops tool activity). Built ONCE in `runMoAEnsemble` and appended at ALL THREE proposer `system:` sites (main via `augmentProposerPromptForTools`, no-tools retry, Skeptic failover). **Rule:** a capability-gated inner path (proposer) must receive EXPLICITLY every piece of context it needs to act — never assume it inherits the outer agent's prompt or the un-stripped history; when a derivation strips messages for pairing-safety, re-supply the task context they carried via a pairing-safe channel (system-prompt text), or the inner path degrades on exactly the follow-ups ("continue") that depend on it. (D2 — the disagreement detector reading collective refusal as consensus — and D3 — weak `utilityModel`/`chatModel` per the operator note — are tracked but NOT fixed here.)
- **Aggregator Constraint:** The Aggregator must NOT be fed consecutive user messages (crashes strict models like Gemma).
- **Inline-synthesis collapse (Sprint 2 — [`docs/moa-aggregator-collapse.md`](docs/moa-aggregator-collapse.md)):** the ensemble's output is NEVER terminal — `runAgent` always runs a final tool-capable `streamText` afterward. On the swarm path that historically meant TWO brain generations per turn (aggregator `generateText`, then the stream re-synthesizing the same drafts). Behind **`settings.aggregator.inlineSynthesis` (default ON since the 2c flip — `DEFAULT_SETTINGS` ships it `true`, so the gate's literal `=== true` is satisfied for every `getSettings()` caller)**, the default synthesis path SKIPS the separate aggregator: `runMoAEnsemble` returns `MoAResult.synthesisHandoff` (drafts + PM #39 marker + `TraceSignals`) instead of a finished `text`, and `agent.ts` injects the ported directive ([`src/prompts/synthesis-inline.md`](src/prompts/synthesis-inline.md) via `loadSynthesisInlineDirective`) + the drafts (`buildInlineSynthesisInjection`) into the SYSTEM prompt (NOT a second user turn — the Aggregator Constraint above) so the existing final stream synthesizes inline — ONE brain generation, and it can call tools mid-synthesis. **Gated narrowly:** only `aggregatorMode === "synthesis"` && reflection OFF && ≥2 successful drafts. Reflection (inherently multi-pass) and tournament (verbatim winner) paths are untouched; a tournament→synthesis fallback keeps `mode === "tournament"` so it does NOT collapse. Trace-memory capture relocates to the stream's `onFinish` on this path (signals plumbed up via `synthesisHandoff`). **Default ON since the 2c flip (2026-06-22)**, after the N=8 live A/B (quality held, latency −31%, completion tokens −16%); opt out with `aggregator.inlineSynthesis: false`. To toggle the production default, change `DEFAULT_SETTINGS.aggregator.inlineSynthesis` (the gate keeps `=== true`).

- **Operator-owned Skeptic — direct model on BOTH skeptic surfaces (PM #90 track).** There are TWO "skeptics": the DPG **reviewer proposer** (fan-out) and the **reflection critic** (`reflectOnResponse`, [`reflection.ts`](src/lib/agent/reflection.ts)). `settings.proposerTiers.skeptic?: ModelConfig` (+ a per-request panel override) pins the model for BOTH via **`resolveSkepticModelConfig(settings, override?)`** ([`moa-personas.ts`](src/lib/agent/moa-personas.ts)) — the single source of truth. Precedence: **per-request override > `proposerTiers.skeptic` > `swarmSandbox.reviewer` > `skepticTier` > persona `modelTier` > derived** (the direct-model knob beats the role→tier knob; the Settings UI warns when both are set). The reflection **revisor** stays on the brain (it writes; only the judge audits). Fallbacks (Sprint-6 reviewer failover, reflection API-retry) are kept but LOUD — they warn naming both models, never silently substitute. `resolveProposerModelConfig` returns the override as the CONFIG but the honestly-resolved `tier` as the telemetry label (never hardcode a tier — QA-audit C2). **Security shape:** a per-request override is `Pick<ModelConfig,"provider"|"model">` ONLY — the `/api/chat` route 400s a smuggled `apiKey`/`baseUrl` (key-injection / SSRF; `createModel` does NOT run `assertSafeOutboundUrl`) or an unknown provider via `isValidSkepticOverride`; keys resolve server-side (`resolveWorkerKey`). **PM #22 threading** (audit A9): threaded through interactive + background + queue-persistence + daemon Auto-Pilot continuation. **Privacy Mode:** the `skeptic` slot joins the tier air-gap check in `assertPrivacyModeAllowsSettings` ([`agent-privacy.ts`](src/lib/agent/agent-privacy.ts)); the per-request override is guarded separately (`assertPrivacyModeAllowsSkepticOverride`, route + runAgent). **Rule:** "the Skeptic" is every place a skeptic/critic judgment runs — pin it once at a single resolver, thread it through every dispatch path, never trust a client-supplied key/URL, and label telemetry with the resolved tier not a constant.
- **Per-request Deep Audit (reflection) toggle (audit A8).** `settings.reflection.enabled` stays the global default (OFF) so the inline-synthesis collapse survives normal turns (a global flip costs ~31% latency on ALL swarm traffic). A per-request `deepAudit` boolean (swarm-panel pill, threaded like `forceSwarm`) overrides it for one run: `reflectionEnabled = deepAudit ?? settings.reflection?.enabled ?? false` feeds BOTH the collapse gate AND the reflection block in `runMoAEnsemble`. Read `settings.reflection?.maxRounds` DEFENSIVELY — it can be undefined when reflection is on via the toggle alone.
- **MoA-Router observability (PM #90).** The Router (DPG) driver is `utilityModel`; when it degrades to static personas the fallback is fail-SAFE but must not be SILENT: `moa-router.ts` emits a success-path line naming the resolved model, and on failure a `moa_router_fallback` `log.warn` + loud stdout line with a `classifyRouterError` reason (`auth`|`not_found`|`timeout`|`schema`|`other`). `/api/health` `utility_model` warns on UNSET / the OpenRouter meta-router pseudo-id (`openrouter/free`|`auto`) / a keyless specific model — a key-presence check alone reports a garbage meta-router as `ok`. **Rule:** a fail-safe fallback on a quality-critical LLM path surfaces its resolved provider/model + a classified reason; usable ≠ authenticated.

- **A free model WITHOUT structured-output support silently disables BOTH differentiating swarm features (verified 2026-07-27).** DPG persona generation ([`moa-router.ts`](src/lib/agent/moa-router.ts)) and the tournament judges' ballots ([`tournament-aggregator.ts`](src/lib/agent/tournament-aggregator.ts)) both go through `generateObject`. On `inclusionai/ling-3.0-flash:free` the provider answers **HTTP 400 `"model features structured outputs not support"`**, so the Router falls back to the three STATIC personas (`analyst`/`creative`/`critic` — no task specialization) and every tournament judge fails → `aggregatorMode: "tournament"` falls back to synthesis. Both fallbacks are fail-SAFE and LOUD in stdout (PM #89), but the run still *looks* like a healthy swarm: you get an answer, 3/3 proposers succeed, and nothing in the UI says the swarm just lost the two things that distinguish it from N-sampling. **Operator rule: `utilityModel` and `aggregator.tournamentJudgeModel` must point at a model with `structured_outputs` support** — only 4 of 15 free OpenRouter models have it (`nvidia/nemotron-nano-9b-v2:free`, `nvidia/nemotron-3-super-120b-a12b:free`, `openai/gpt-oss-20b:free`, `google/gemma-4-26b-a4b-it:free`); the proposers and brain do NOT need it. Check with `supported_parameters` on `/api/v1/models` before configuring a free tier — `tools` support does NOT imply `structured_outputs` support (11 of the 15 free models have tools but not structured outputs). **Rule:** a capability-gated feature whose fallback is fail-safe still needs a health signal — "it answered" is not evidence the feature ran.
- **Proposer-reliability is the binding constraint on swarm quality — do NOT run the swarm on OpenRouter `:free`-tier proposers (verified 2026-07-06).** The swarm's value is gated on proposer SURVIVAL, not on the Skeptic model: the aggregator needs ≥2 successful drafts, and the Deep-Audit reflection critic only runs if aggregation produced an answer to critique. In a live 6-run matrix, `nvidia/nemotron-3-super-120b-a12b:free` proposers died under parallel load in **3 of 6 runs** (0/3, 0/3, 1/4 successful) — free-tier models are shared-quota upstream-rate-limited (HTTP 429 `Provider returned error`) and buckle exactly when 3–5 fire at once through the `agentSemaphore`. When <2 drafts survive: aggregation is skipped, **Deep Audit is skipped (nothing to critique)**, and a pinned premium Skeptic (e.g. Sonnet) NEVER runs its audit — the turn silently answers as a plain single agent. **Operator policy (not a feature): put reliable PAID models in `proposerTiers.{fast,balanced,frontier}`** (`deepseek/deepseek-chat` works well); a strong pinned `proposerTiers.skeptic` is worthless behind dying proposers. The failover chain itself is SOUND (loud, layered — Sprint-6 reviewer failover + reflection API-retry, both verified firing on a bad model id); the risk was never failover, it was upstream proposer death. **The unintended collapse is now SURFACED (`degradedToSingleAgent`):** when 0 proposers survive, `runMoAEnsemble` sets the flag, and `agent.ts` emits a `console.warn` + a UI `publishUiSyncEvent` note ("Swarm stopped: all N proposers failed … single agent, no Skeptic audit") — distinct from a deliberate Router `bypassed`. **Rule:** a swarm turn that collapses to a single agent must SAY SO — a silent degradation is indistinguishable from a healthy answer, and the operator's most likely fix (swap the proposer tier off free) is invisible without the signal. Regression: the "degradation signal" block in [`moa.test.ts`](src/lib/agent/moa.test.ts). Model-probe facts durable in [[orchestra-session-handoff]] — free models 429 (`llama:free`/`qwen3:free`/`gpt-oss:free` all dead at test time); WORKING: `deepseek-chat`, `openai/gpt-4o`, `anthropic/claude-sonnet-4.6`, `nemotron-120b:free` (works solo, flakes under swarm parallelism). Weak-Skeptic parse-miss fear did NOT reproduce (nemotron emitted valid JSON verdicts, 0 misses) — do not build a parse-miss retry.

- **Free-tier failover: layered delivery recovery on the proposer path (2026-07-26 track).** The thesis is an ENGINEERING claim — *"failover raises free-tier DELIVERY"* (measurable) — deliberately NOT *"the swarm reasons better"* (tested extensively, never demonstrated; see the eval docs). Three layers, innermost first:
  1. **Retry-on-empty (shipped `9822966`).** A throttled free endpoint answers HTTP 200 with an EMPTY body. `ORCHESTRA_PROPOSER_EMPTY_RETRIES` (default 2, backoff 2s→4s) re-issues the generation; `buildProposerSignal()` rebuilds a FRESH `AbortSignal.any([parent, timeout])` per attempt (a reused expired signal aborts the retry instantly) so the parent-abort chain still holds. `ORCHESTRA_PROPOSER_TIMEOUT_MS` (default 120000) makes the per-proposer budget operator-tunable. A THROWN throttle (429) is retried on the same budget — it used to skip the loop entirely and kill the proposer on the spot, because the loop only knew how to retry an empty 200 (the SDK's own `maxRetries: 2` retries on a ~ms ladder; this adds the multi-second wait a shared quota needs). The backoff carries **up to 40% jitter** (proposers that hit the same endpoint at once would otherwise wake at the same millisecond and re-fire in lockstep, re-creating the burst one layer down) and is ABORT-AWARE (a plain sleep kept firing retries and burning credit after the user pressed stop, since each attempt builds a FRESH signal). **⚠️ The measured "delivery 4/6 → 5/6" claim is WITHDRAWN (2026-07-26).** It was an artifact of the EVAL HARNESS, not a property of the agent: `invokeRealAgent` extracted the answer as "last assistant message wins", which scores a turn answered through the `response` TOOL (PM #61's delivery channel) as EMPTY — the last assistant message is then the tool-CALL carrier with `content: ""`. Cross-checking every scored-empty case against its persisted chat (`data/.trash/chats/`, PM #63) found a real 101–1181-char answer in ALL of them; across ~300 eval chats exactly ONE has no answer. Fixed by `extractDeliveredAnswer` ([`evals/runner.ts`](src/lib/evals/runner.ts), regression in `runner.test.ts`). What the runs DO support: empty bodies are frequent at the PROPOSER layer (8 events in one 6-case run, jittered backoff visible in the log) and the retry recovers them — so the value is fewer LOST DRAFTS and no silent blank turns, NOT an end-to-end delivery-rate gain. Run-to-run variance dominates at N=6 (two runs of the same build: 5/6 vs 3/6 passes). Full write-up: [`docs/free-tier-failover.md`](docs/free-tier-failover.md). **Rule: before reporting a metric moved, verify the instrument reads the same channel the system delivers on.**
  2. **Circuit breaker + cross-model substitution ([`model-health.ts`](src/lib/agent/model-health.ts)).** Retry cannot fix a PERMANENTLY dead endpoint — it just burns 6s of backoff per proposer per turn while hammering a rate-limited shared endpoint. `recordModelFailure`/`recordModelSuccess` track CONSECUTIVE failures per `provider/model`; N (default 3) trips the circuit for a cooldown (default **5 min** — a free endpoint's availability fluctuates by the minute, so a long cooldown keeps substituting away from a model that already recovered, which itself costs delivery). **Reads are PURE and the half-open probe is explicit** (`isModelCircuitOpen` vs `tryAcquireProbe`): the first cut healed the entry as a SIDE EFFECT of the read, so the moment the cooldown expired EVERY proposer in the fan-out saw "closed" and the whole herd hit a maybe-dead endpoint — the opposite of half-open. Exactly one probe is handed out (a `probeInFlight` flag, lock-free because Node runs the check-and-set in one tick); a failed probe restarts the cooldown, a successful one fully heals. **Failures require POSITIVE evidence:** `classifyModelFailure` returns `throttle`/`server`/`unreachable` for recognised endpoint-side signatures and `null` for everything else — an over-long prompt (400), a full semaphore queue, a local `TypeError`. Counting those let an ORCHESTRA bug mark a healthy model dead for every concurrent chat; a breaker must open on evidence, never on ignorance. `selectHealthyConfig(preferred, pool)` substitutes the first closed-circuit model from the run's `failoverPool` (every configured `proposerTiers` slot + the worker config, key-resolved) rotated by the proposer INDEX so concurrent proposers pick DIFFERENT substitutes (without the rotation the whole fan-out lands on one endpoint and that one absorbs the entire burst), and is evaluated AFTER the stagger, so it reads the FRESHEST breaker state — the point of staggering is to let earlier proposers report an endpoint's health before later ones commit to it. **One failure per PROPOSER, recorded only on retry EXHAUSTION — never one per attempt (audit A2).** The counter is shared by every concurrent proposer on an endpoint, so per-attempt recording made N proposers each hitting ONE transient empty look like N consecutive failures: spurious open → in-flight retries abandoned → drafts lost, regressing the very delivery metric the track exists to raise. A transient empty that recovers leaves no mark. **Fails OPEN by construction:** when every candidate is dead it returns the operator's own choice — a breaker that can block a run is worse than the throttling it guards against (PM #60 posture). State is in-memory on a `Symbol.for()` `globalThis` singleton (PM #71 — the health route and the agent path are separate module graphs). A parent abort is NEVER recorded as an endpoint failure; a TIMEOUT is (too slow = dead for this turn). Surfaced in `/api/health` as `model_endpoints`. Escape hatch + tunables in "Runtime invariant escape hatches".
  3. **Pacing the fan-out ([`proposer-pacing.ts`](src/lib/agent/proposer-pacing.ts)).** The only layer that PREVENTS the failure instead of recovering from it: 3–5 proposers firing at the same instant, through one key, at one shared free endpoint is what produces the empty 200s. `computeStaggerMs(index, config)` replaces PM #66's uniform `index * 250ms` with an ENDPOINT-AWARE offset — paid endpoints keep the PM #66 profile exactly, free endpoints get a wider base (`ORCHESTRA_FREE_STAGGER_MS`, default 900), and an endpoint the breaker has already seen fail gets `+1500ms` per consecutive failure, all capped at 8s so a slow start can never dominate the turn. `withFreeTierPacing(config, fn)` additionally bounds CONCURRENT free-tier dispatches (`ORCHESTRA_FREE_TIER_CONCURRENCY`, default 2; **0 disables the cap**) on a process-global semaphore — shared across chats, because two chats firing 5 free proposers each is the same herd as one chat firing 10. **ORDERING CONTRACT (audit A1): acquire the free-tier budget OUTSIDE the global `agentSemaphore`, never inside it.** The free budget is an unbounded wait on a REMOTE quota; `agentSemaphore` bounds MACHINE load and is shared with `memory.ts` embeddings and the main agent path, with as few as 2 permits on a 16 GB box — nested the wrong way, a proposer queued on the free quota sits on a scarce global permit and starves the rest of the process. The stagger sleep is ABORT-AWARE (`abortableSleep`, audit A3): the offset can reach 8s, so a plain `setTimeout` would keep a cancelled turn's proposers queued after the user pressed stop; it RESOLVES (never rejects) on abort, because a rejection would be caught by the proposer's try/catch and mislabelled as an endpoint failure. "Free" is the literal `:free` OpenRouter id suffix (a naming FACT, so it cannot mis-classify a paid model); `ORCHESTRA_PACE_ALL_MODELS=true` forces pacing everywhere. Pure latency shaping — it never changes WHICH model runs. **Measured caveat (do not overclaim):** the global `agentSemaphore` already caps concurrency by RAM tier (**2 permits on a 16 GB box — the operator's**), so on that machine the free-tier cap is near-redundant and the STAGGER widening is what actually changes behaviour; the cap earns its keep on 32 GB+ machines (4–16 permits) and across concurrent chats.
  4. **The BRAIN's own delivery failover ([`final-answer-failover.ts`](src/lib/agent/final-answer-failover.ts)).** Layers 1–3 harden the PROPOSER fan-out; the final `streamText` that actually answers the user had none of it. When a throttled endpoint returned an empty body, PM #69's forced final answer ran ONCE on that same endpoint, got another empty body, and `resolveTurnContinuation` returned `{ text: "" }` **silently** — a blank turn indistinguishable from an Orchestra bug, and the worst delivery failure in the stack because unlike a dropped proposer it has no survivors. `generateFinalAnswerWithFailover` makes it a bounded ladder: brain → ONE jittered abort-aware retry → ONE attempt on a healthy substitute from the operator's own settings (`buildFinalAnswerPool`: `utilityModel` + the `proposerTiers` slots — settings-only, so Privacy Mode's air-gap holds), each substitution announced LOUDLY in the turn's UI notice. An undeliverable turn now always carries `UNDELIVERABLE_NOTICE` (what happened + what to do) instead of silence. The substitution at step 3 is deliberately NOT gated on the brain's breaker threshold — within the turn we have first-hand evidence it just failed twice, and waiting for the global threshold would ship a blank turn while a healthy model sits unused. **It NEVER replays the tool-capable stream:** "zero output reached the client" does not prove the remote side executed nothing (a tool may have run before the stream dropped), so every attempt is TOOL-LESS by construction — the worst case is a wasted generation, never a repeated side effect. Threaded from `agent.ts` via `resolveTurnContinuation({ brainConfig: resolvedModelConfig, … })`; without `brainConfig` the helper degrades to the pre-Sprint-3 single attempt. Regression: [`final-answer-failover.test.ts`](src/lib/agent/final-answer-failover.test.ts).
  5. **Degradation policy — the USER chooses ([`degradation-policy.ts`](src/lib/agent/degradation-policy.ts)).** Layers 1–4 substitute a healthy model when the configured one is dead, which is the right DEFAULT but not a universal answer: a substituted model is a DIFFERENT model, so "same quality, just slower" would be a dishonest pitch. `settings.degradationPolicy` (+ a per-request override, swarm-panel pill) picks: **`speed`** (default — substitute, and always SAY which model answered instead of which), **`quality`** (never substitute; retry the user's model, then report honestly), **`ask`** (never substitute; the closing notice offers the choice for the next turn). `resolveDegradationPolicy(settings, override, { background })` is the single resolver; `allowsModelSubstitution(policy)` gates BOTH substitution sites (proposer fan-out in `moa.ts`, brain ladder in `final-answer-failover.ts`). **Background/Auto-Pilot is FORCED to `speed`** — an unattended run has nobody to read a "try again later" notice. **PM #22 threading:** interactive route + background dispatch + queue persistence + daemon continuation + Zustand panel state, with the `/api/chat` body validated by `isDegradationPolicy` (an unknown string falls back to settings — a malformed client must never widen what Orchestra may substitute). **Honest limitation of `ask`:** Orchestra has NO mid-turn user-input primitive (SSE is one-way, the chat surface is turn-based), so `ask` cannot pause a running turn and pop a dialog — it asks at the end of the turn, once the pool is exhausted. Per-empty-body prompting was rejected outright (one observed run logged 14 empty bodies — 14 modals would be unusable), and faking a blocking prompt the runtime cannot honour would be worse than not having one.
  - **Rule:** a retry loop is only the innermost layer of availability. Pair it with (a) a breaker so a dead endpoint stops consuming the retry budget, (b) a substitution pool so the run still completes, and (c) a LOUD signal at both — substitution that the operator cannot see is indistinguishable from a healthy run (the `degradedToSingleAgent` lesson applied one level down). **Dispatch failures are contained (R1):** both semaphores can throw *before* the per-proposer try/catch is entered (`Semaphore.acquire` rejects past `maxQueue`), which would reject the `Promise.all`, make `runMoAEnsemble` throw, and collapse the ENTIRE ensemble over a local capacity problem — the fan-out now wraps the whole dispatch and returns an error draft instead. Regression: [`model-health.test.ts`](src/lib/agent/model-health.test.ts) + the "free-tier failover Sprint 1" block in [`moa.test.ts`](src/lib/agent/moa.test.ts). NB: `moa.test.ts`'s top-level `beforeEach` MUST call `resetModelHealth()` — the process-global breaker otherwise leaks substitution from one failure-path test into every later test.

### 2. Project Blackboard (`src/lib/memory/blackboard.ts`)
- **Shared Fact Storage:** Agents write to `.orchestra_blackboard.json` using vector embeddings. This allows independent agents to share and retrieve canonical truths across the entire project lifecycle without relying on linear chat history.

### 2b. Deep-Memory Recall — chat-scope auto-archived raw history (PM #85)
- `runAgent` injects a passive `<deep_memory_recall>` block into the system prompt: a `searchMemory` over the chat's memory pool (`data/memory/<projectId|main>`), keyed on the user message. The compaction path (Sprint A4) auto-archives a chat's evicted RAW history (verbatim + summary, `area: AUTO_ARCHIVE_AREA`) INTO that same pool.
- **BOUNDED at the injection site (PM #95).** `deepRecallLimit=3` caps the chunk COUNT but NOT each chunk's SIZE — and auto-archived VERBATIM chunks run tens of thousands of tokens, so on an aged chat recall ballooned to 82K+ tokens of the system prompt and mode-collapsed the brain (the in-flight governor can't help — the bloat is in the SYSTEM prompt it never prunes). `buildBoundedRecallBlock` ([`deep-recall.ts`](src/lib/agent/deep-recall.ts)) caps the injection per-chunk head+tail (`DEEP_RECALL_PER_CHUNK_CHARS=4000`) AND total (`DEEP_RECALL_TOTAL_CHARS=16000`); the full verbatim archive stays reachable via an explicit `searchMemory`/`memory_load` tool call. **Rule:** a passive injection from a growing store must be bounded per-item AND total, independent of any item-COUNT cap. **PM #95 — the budget is WINDOW-RELATIVE (`resolveRecallBudgetChars(effectiveWindowTokens)`, [deep-recall.ts](src/lib/agent/deep-recall.ts)): ~8% of the model's EFFECTIVE (reliable-capped) window, bounded `[4K, 200K]` chars**, so a big-window model (Claude 200K, Gemini 1M) carries richer recall inline while a small window stays safe. At the operator's ~120K window the cap lands ~33.6K chars — above the old fixed 16K but rarely BINDING (typical recall is a few K chars), so no behavioural change on normal traffic.
- **The contamination (PM #85):** all GLOBAL (no-`projectId`) chats share ONE pool (`data/memory/main`). Auto-archived raw history from a one-off chat was recalled into UNRELATED later chats by semantic match (the `telegramattacker`→unrelated-chat leak), because archive-insert and recall-search use the SAME `projectId ?? "main"` subdir and recall had no owner filter.
- **Contract:** auto-archive inserts are stamped `{ chatId }`; `filterDeepRecall` ([`compressor.ts`](src/lib/agent/compressor.ts)) drops any `AUTO_ARCHIVE_AREA` hit whose `chatId` ≠ the current chat BEFORE the top-N cap (over-fetch `limit × 4` → filter → cap, so a foreign archive can't crowd out a legitimate hit). Applied uniformly (project + global). **Auto-archived RAW history is a WITHIN-chat continuity aid only** — cross-chat knowledge belongs to the Project Blackboard (§2) and CURATED `insert_memory` facts (areas `main`/`solutions`/`fragments`), which are deliberately untouched and still cross chats. **Rule:** a passive injection sourced from a shared store must be scoped to its legitimate owner — stamp owner metadata at write, filter by it at read.
